# PianoTimer v0.1：可编译的实验原型

**这不是已经通过人声排除测试的成品。** 第一版包含麦克风输入、实验性钢琴声候选检测、累计时间、1 秒短停顿补计与 Reset。真实钢琴、人声和环境噪声的准确率尚未测量。

## 使用顺序

1. 优先按 [屏幕离线录音指南](RECORDING.md) 在钢琴旁点击 Record，回电脑后导出 WAV 听检，并按指南确认配置。原有 MicTest 串口采音仍可用于排查。
2. 打开 `/Users/leon/iot-pianoTimer/PianoTimer/PianoTimer.ino`。
3. 使用与 MicTest 相同的板型、16MB 分区、OPI PSRAM 和 USB 设置。不要擦除整个 Flash。
4. 上传；串口监视器改为 **115200 baud**。
5. 上电后保持安静约 **4 秒**，程序校准背景噪声。校准期间不计时；如果这时弹琴，可能造成阈值偏高，应复位重新校准。
6. 屏幕显示 HH:MM:SS、检测状态、音量条和 Reset。英文界面沿用现有字体，无需安装额外中文字体。
7. 如果显示 `I2S left: tap Record`，说明还没有保存麦克风配置；可直接通过 Record 录音听检，计时暂不启用。若显示音频错误或校准失败，计时停止，先排查采音。

## 计时规则

- 音频按 128ms 小段处理。钢琴候选需相邻片段支持，首片段会回填；界面有约 1–2 个片段的判断延迟。
- 检测到钢琴时累计；识别到的余音也计入。
- 中间静音 **≤1 秒**且之后再次检测到钢琴，补计该间隔。
- 静音 **>1 秒**，整段不计，包含最开始等待的那一秒。
- 停止后不会赠送 1 秒；末尾待确认声音可能少计一个片段。
- Reset 清零累计和等待补计状态，重启采音以丢弃旧缓存；麦克风模式保留。
- 录音丢失、持续无效数据、采集失败时停止计时，不能把丢失音频当作可补计静音。
- 1 秒比较在计时逻辑中精确到微秒，但实际声音边界受到 128ms 分帧和识别误差影响。
- 断电不保存本次累计时间；小时可超过 99，内部使用 64 位时间。

## 检测实现和边界

`libraries/PianoAudio/src/PianoDetector.h` 使用 Hann 窗、2048 点 FFT、背景噪声门限、谱平坦度、谱峰集中度、多峰结构、起音与后续频谱稳定性判别钢琴声候选。它不是仅根据音量触发，也不是训练好的机器学习模型。

它可作为端到端联调基线，但不能保证区分钢琴、人声、哼唱、其他乐器或钢琴录音。轻声、低音、较纯的音色和混合讲话可能漏检，富含谐波的人声可能误检，单次起音超过约 8 秒的长余音会停止作为候选。持续泛音、踏板共鸣也需要真实数据验证。

在实际录音完成之前，不宣称符合“可靠排除人声和噪声”的最终要求。下一阶段应使用本设备实录数据评估，并决定调整特征或训练小型声音分类模型。训练/验证集需按不同录音时段划分，不能将同一录音的相邻片段分别当作训练和测试来夸大效果。

## 验收清单（需在真钢琴旁完成）

| 项目 | 预期 |
| --- | --- |
| 安静 30 秒 | 时间不增加 |
| 单独说话 30 秒 | 时间不增加；否则记录为误检 |
| 风扇、拍手、桌面敲击 | 不持续计时 |
| 连续弹奏 30 秒 | 接近实际有效时长，记录漏计量 |
| 轻声和低音练习 | 检查是否漏计 |
| 弹奏 → 短停约 0.5 秒 → 弹奏 | 短停补计 |
| 弹奏 → 停 3 秒 → 弹奏 | 3 秒全部排除 |
| 每 5 秒单独弹一次 | 不将全段连起来计时；真实余音仍可计入 |
| 弹奏同时说话 | 钢琴仍应计入，需验证混合声音效果 |
| 在等待期间 Reset | 清零，随后不会补回清零前的间隔 |

串口 CSV：`db,flatness,tonal,peaks,candidate,total_us`。`candidate` 是规则判别结果，不是概率或经过校准的置信度。


## 双核 CPU 占用率（2026-11-11）

音量条与 Reset 之间显示 `CPU0 xx%    CPU1 xx%`，每秒刷新一次，分别表示两个核心在最近采样窗口内的占用率（每核 0–100%，不是两核合并后再平均）。

使用 FreeRTOS 各核心空闲任务的运行时间差，以 `100 × (1 − 空闲时间 / 经过时间)` 计算。每核有一个优先级 1 的轻量采样任务，每秒唤醒，确保本核心空闲任务的统计值已在切换时更新；不进行空转测速或开机满负荷校准。数值是系统调度统计口径的近似负载，不是独立中断耗时剖析，采样自身也占用少量 CPU。

启动后约 1–2 秒出现读数；统计功能不可用、任务创建失败或超过 3 秒未采到数据时显示 `--%`。显示由 LVGL 定时器更新，不依赖麦克风读数：等待配置、校准、暂停和采集错误状态下仍可刷新。Reset 只清空练琴时间，不清空 CPU 统计。

本版使用 Arduino-ESP32 3.3.12 已启用的运行时间统计，无需修改 SDK 配置。实机检查：观察两核读数，比较静音和处理声音时的变化，并检查 CPU 文字与 Reset 是否有遮挡；尚未完成此实机检查。


## 屏幕离线录音（2026-11-11）

底部增加 Record，与 Reset 并排。3 秒准备倒计时后采集 5 秒音频到 PSRAM，再写入内置 FFat 数据区并逐字节读回校验，成功显示 Saved 与独立文件编号。详细操作见 [RECORDING.md](RECORDING.md)。

无电脑时可以录音；USB 导出另用 `tools/export_recording.py`。录音仅保存原始声音，不会自动标定或训练模型。未配置麦克风时按用户已确认的 I2S 左声道提供录音，听检后人工 verify 才持久保存设置。


## 不计时排查与校准修正

背景噪声校准现在跳过麦克风启动后的前4帧（512ms），再收集24帧，使用下四分位数估计背景，避免启动瞬态和偶发碰撞把门限抬高。总计约3.6秒，期间保持安静。仍不能在持续弹琴或讲话时校准。

未计时状态会显示：`Below threshold`（同时显示当前dB和门限）、`Audio clipping`、`Not piano-like yet` 或 `Waiting for stable piano`。请记录弹琴时实际出现的文字；不能据此直接假定都是同一种故障。特征判别条件此次没有放宽，人声排除仍待验证。
